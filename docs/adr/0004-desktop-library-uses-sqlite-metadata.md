# ADR-0004：桌面素材库使用 SQLite 保存元数据

## 状态

已接受

## 背景

桌面版需要把任务、收藏、Agent 对话和文件索引长期保存在用户选择的素材库目录。单个 JSON 文件需要频繁整体重写，崩溃时容易损坏；按记录拆成大量 JSON 文件则会增加跨记录引用、事务和清理成本。图片本身仍需要作为用户可访问的普通文件存在。

## 决策

桌面版把结构化元数据保存在素材库目录的 `metadata/awai.db` SQLite 数据库中，把生成图、参考图和导出文件分别保存在 `generated/`、`references/` 与 `exports/`。数据库只保存文件相对路径，不保存图片二进制。

首次启动预填系统“文档”目录下的 `AWAI创作工作台` 作为素材库建议位置。用户确认或选择其他目录后，应用才创建素材库结构并写入数据；不能在用户确认前静默创建素材目录。

已有素材后更改位置使用“迁移素材库”流程。应用把数据库和所有受管文件复制到新目录，校验 SQLite 可打开、schema 版本正确且登记文件完整后，才把新目录设为当前素材库。旧目录不自动删除，避免迁移后无法回退；运行任务期间不能开始迁移。

启动时当前素材库路径不可访问，应用停在恢复入口，只允许重试连接或让用户重新定位已有素材库。应用不得在原路径自动创建同名空目录，也不得把不可访问误报为没有历史数据。

涉及任务与文件的写入先把图片写入临时文件并原子重命名，再提交数据库事务；失败时清理未登记的临时文件。数据库 schema 使用显式版本号和顺序迁移。

AWAI 备份包不直接包含 `awai.db`，而是导出带格式版本的 JSON 清单和对应图片文件。导入时校验清单后，通过当前版本的数据访问层写入 SQLite，并按非覆盖合并规则处理 ID 冲突。

## 后果

桌面运行时需要 SQLite 数据访问适配器和数据库迁移测试，但可以获得事务、索引和崩溃恢复能力。用户仍能直接访问图片文件，备份包也不与某一 SQLite schema 或平台实现绑定。
